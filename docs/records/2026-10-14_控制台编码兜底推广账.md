# 2026-10-14 · 控制台编码兜底「推广到剩余脚本」

> **背景**：Windows 控制台默认 **GBK(cp936)**，而 `evals/` 与 `scripts/` 下的命令行脚本会往控制台
> 打 `✅` / `❌` / `⚠️` —— GBK **编不出这些符号** ⇒ `UnicodeEncodeError`，
> 而且**崩在"打印结果"那一步**：用户看到满屏 traceback，**而不是结果本身**。

---

## 一、这不是新问题，项目里**早有做法**（本轮只是推广）

`evals/reset_eval_threads.py:46-53`（2026-09-24 踩过之后加的）：

```python
# ⚠️ Windows 控制台默认是 GBK，而本脚本要打 ✅ / 中文 —— **不统一成 UTF-8 会直接崩**。
# 2026-09-24 实测踩到：删完并 VACUUM 之后**崩在最后一行**
#   （`UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`）
#   ⇒ 看起来像"清理失败了"，实际早就成功了 —— 典型"静默误导"。
for _stream in (sys.stdout, sys.stderr):
    if hasattr(_stream, "reconfigure"):
        _stream.reconfigure(encoding="utf-8", errors="replace")
```

**本轮开始时已经有 3 个脚本这么做了**：`evals/reset_eval_threads.py` · `scripts/probe_mcp_server.py` ·
`app/code_agent/agent/code_agent.py`。

## 三、同一轮补进 `AGENTS.md` 的「已知坑」（3 条）

| 加到哪 | 内容 |
|---|---|
| 🔴 **MCP 子进程必须固定 UTF-8** | `utils/mcp.py` 设 `PYTHONIOENCODING=utf-8`。子进程 stderr 默认 GBK，父进程按 UTF-8 解 ⇒ **子进程一打中文就 `UnicodeDecodeError`**（实测卡住 RAG 集成测试，崩在 `contextmanager.__exit__` 里，看着完全不像编码问题） |
| ⚠️ **控制台脚本要打 ✅/❌ 就必须先切 UTF-8** | 指向 `reset_eval_threads.py` 那 4 行，说明"崩在打印结果那一步"这个坑 |
| ⚠️ **依赖服务只绑 `127.0.0.1`** | + searxng 端口走 `SEARXNG_PORT`（默认 8888）；**被 Windows 保留区间占住会报 `10013`、容器起不来**（实测 8888 落在 `8875–8974`）；Docker Desktop 的「Start」对这种情况没用，必须 `--force-recreate` |
