# 2026-10-09 · token 计量明细 + 启动脚本修复账

> 一天之内做的两件事，都属于**用户实测驱动**：① token 只统计总数、拿不到"输入/输出/缓存命中"，
> 且 provider 不返回 usage 时**静默按 0**；② 双击启动脚本**闪退**（端口被系统保留 + 退出码恒为 0）。
> 写法沿用本目录惯例：**现象 → 根因 → 修法 → 证据**。

---

## 一、token 计量：从"只有总数"到"计费原料"

**现象 1（口径缺失）**：状态条与结果卡只有一个 token 总数，看不出输入/输出/缓存命中各多少；
用户问"为什么缓存命中了却不体现"。

**根因**：采集层只取了 `usage_metadata["total_tokens"]` 一个数（`multi_agent._msg_tokens`），
`input_tokens` / `output_tokens` / `input_token_details.cache_read` 全被丢掉；
而这三项正是**将来按各家单价折算成本**的必需原料（只留 total ⇒ 历史永远算不回来）。

**现象 2（真 bug：预算闸门静默失效）**：provider 不返回 usage 时按 **0** 计 ⇒ 任务级 token 预算
`max(50 万, 4×窗口)` 这条闸门等于不存在，且**不报警**。

**修法**：
- 新增 `app/code_agent/agent/usage.py`（纯函数）：`normalize_usage` + `merge_token_detail`，
  三家缓存字段名都认（langchain 的 `input_token_details.cache_read`；兜底 `prompt_cache_hit_tokens` /
  `cache_read_input_tokens`）；**缺字段留 `None`，不猜 0**；缺 usage 标 `unmetered`。
- `AgentState` 新增 `token_detail` 通道（**同步进 `PER_TURN_RESET`**）；planner / executor / verifier
  三处累加点保留明细 + 模型名 + 时间戳 + `by_model` 分桶。
- `CancelToken` 增加 `token_detail` / `unmetered_calls`，状态条带出 `inputTokens` / `outputTokens` /
  `cacheReadTokens` / `unmeteredCalls`；前端状态条与结果卡显示三项明细，未计量时显式提示。
- `evals/runner.py` 归档里带上 `token_detail`（将来折算成本时历史轮次也能重算）。
- **口径**：只计量、**不算钱**（没有价格表 —— 各家单价不同、会调价、还有峰谷价与缓存价）。

**现象 3（真机验收时抓出的漏计）**：14 步的任务在结果卡上写「**8 次调用未返回用量**」，但 DeepSeek 明明返回。

**根因**：累加循环把 `output["messages"]` 里的**每一条**消息都当成一次模型调用 ——
而 `astream` 的块里除了 `AIMessage` 还有 `ToolMessage`（工具结果，天然没有 usage）。

**修法**：只对 `AIMessage` 计用量。回归测试
`tests/test_token_detail.py::test_tool_messages_are_not_counted_as_calls`（并补了一条
`test_ai_message_without_usage_is_flagged` 证明"真的缺"仍会被标出来）。

**现象 4（另一处漏计，改动前就存在）**：`route_node` 那次复杂度分类的模型调用**从来没计过用量**
（`_llm_classify_complexity` 只取结论、把 usage 丢了）。

**修法**：该函数返回 `(结论, usage)`，`route_node` 计进 state 与状态条。测试
`test_router_usage_is_counted`。

**证据**：
- 单元/集成：`tests/test_token_detail.py` **17 条**（字段归一化三家写法、缺失不置 0、累加语义、
  `by_model` 分桶、通道复位、工具结果不计数、路由计数）
- 真机（真实 DeepSeek，端口 8300）：状态条
  `1.2 万 / 51.2 万 token（输入 1.2 万 · 输出 468 · 缓存命中 1.0 万）`；结果卡
  `打回 0 次 · 步数 3 · token 12009（输入 11541 / 输出 468 / 缓存命中 10112） · 耗时 44.1s`，
  **无**未计量误报。截图：`docs/evidence/token明细-2026-10-09/`
- 厂商字段实测（一次极小真实请求）：DeepSeek 同时返回 `prompt_cache_hit_tokens` 与
  `prompt_tokens_details.cached_tokens`，并单列 `completion_tokens_details.reasoning_tokens`
  （推理 token 按**输出**计价）
- 全量：`pytest` **743 passed**（723 → +20）· 覆盖率 78% · `ruff check` + `format --check` 全过

## 二、启动脚本：闪退 + 端口被系统保留

**现象**：双击 `scripts\run\start-app.cmd` **窗口一闪而过**，看不到任何错误。

**根因（两条叠加）**：
1. **退出码没传出去**：`& uv run uvicorn …` 绑定失败**不会**成为 `powershell.exe` 的退出码
   ⇒ `.cmd` 末尾的 `if errorlevel 1 pause` 不触发 ⇒ 窗口直接关闭。
2. **端口探测方法不对**：旧实现用 `Get-NetTCPConnection -State Listen`，只看得见"有没有人在监听"，
   **查不出"端口被 Windows 保留"** ⇒ 打印「端口 8000 空闲」，紧接着绑定报
   `[Errno 13] … [winerror 10013]`（Hyper-V/WSL 的 `excludedportrange` 把 `7927–8126` 划走了；
   触发时机是 Docker/WSL 网络栈重启，**每次随机重划**）。

**修法**：
- 端口改成**真 bind 实测**（`TcpListener`），失败原因翻成人话：
  **`10048` = 被进程占用**（给 PID）/ **`10013` = 被系统保留**（给查询命令与两条出路，**别去杀进程**）。
- **自动退避**：`-Port`（默认 8000）→ 8010 → 8020 → 8300 → 8310 → 9000 → 9010 → 9200，
  每个都实测；换端口时打印「✗ 8000 被系统保留 … → 已自动改用 8300」。新增 `-NoFallback`。
- 结尾 `exit $LASTEXITCODE` ⇒ 失败时退出码非 0，窗口会停住显示错误（不再闪退）。

**同一天还踩到一个"改一次就可能复发"的坑**：用编辑器改 `.ps1` 时**丢掉了 UTF-8 BOM** ——
`.cmd` 调的是 **Windows PowerShell 5.1**，它读无 BOM 的 `.ps1` 会按 ANSI(GBK) 解 ⇒ 中文乱码、
**中文字符串末尾的引号被吞** ⇒ 语法直接坏（`pwsh` 7 下却正常，所以只有双击启动的人会撞上）。

**修法**：补回 BOM + 加机械守卫 `tests/test_launcher_scripts.py`（3 条：所有 `.ps1` 带 BOM /
结尾有 `exit $LASTEXITCODE` / 端口探测用真 bind 且区分 10013 与 10048）；
`AGENTS.md` 增「启动脚本（Windows）」一节，`scripts/run/README.md` 增「端口是怎么选的」。

**证据**：`-NoFallback` 下报「端口 8000 被系统保留」且**退出码 1**；默认路径自动改用 **8300**
并正常启动（应用打印 `[OK] 已就绪 http://127.0.0.1:8300/`）。
